# ClaudeBridge

Плагин для **Purpur / Paper 26.2**, который даёт ИИ (Claude или любой другой нейросети) доступ к серверу через HTTPS API:

- **Администрирование:** консольные команды с выводом, состояние сервера (TPS, MSPT, память, игроки, миры), логи с поиском.
- **Плагины и файлы:** список плагинов, просмотр файлов сервера, поиск по имени и по тексту. Только чтение и только внутри папки сервера.
- **Базы данных:** SELECT-запросы к SQLite и MySQL/MariaDB. Только чтение, причём запись блокируется дважды: проверкой запроса и режимом соединения.
- **Игра:** аватар ИИ в мире, фигура игрока с именем `Claude`. Он ходит с поиском пути, следует за игроком, копает с реальным временем добычи, ставит блоки, открывает двери, пользуется сундуками и печами, крафтит, дерётся, пишет в чат и читает его.

Инструкция для нейросети: **[AI_GUIDE.md](AI_GUIDE.md)**. Передайте её ИИ-агенту вместе с адресом API.

## Как это работает

Плагин поднимает веб-API. ИИ отправляет HTTPS-запросы, а плагин выполняет их внутри сервера. Это не туннель игрового трафика: аватар существует на сервере, и ИИ управляет им командами. Поэтому ИИ, у которого есть только доступ к вебу (как у облачного Claude), может и администрировать, и «играть».

## Установка на хостинге без свободных портов (туннель)

Это вариант для игрового хостинга, где открыт только игровой порт. Плагин сам скачивает и запускает программу-туннель. Она подключается к Cloudflare или ngrok **только исходящим** соединением, а сервис выдаёт публичный адрес `https://…` с действующим сертификатом на порту 443. Входящие порты не нужны.

1. Положите `ClaudeBridge-1.3.0.jar` в `plugins/`; блок `http:` в `config.yml` оставьте по умолчанию (`bind: 127.0.0.1`, `port: 8765`, `tls.mode: off`).
2. Выберите провайдера в `config.yml`:
   - **Cloudflare**, регистрация не нужна:
     ```yaml
     tunnel:
       provider: cloudflare
     ```
     Адрес вида `https://слово-слово-слово.trycloudflare.com` меняется при каждом перезапуске сервера.
   - **ngrok**, адрес постоянный: зарегистрируйтесь на ngrok.com (бесплатно) и скопируйте authtoken со страницы https://dashboard.ngrok.com/get-started/your-authtoken:
     ```yaml
     tunnel:
       provider: ngrok
       ngrok:
         authtoken: "ваш-токен-ngrok"
     ```
3. Выполните `/claudebridge reload` или перезапустите сервер. Через несколько секунд в консоли появится:
   ```
   [ClaudeBridge] Tunnel: downloading https://...
   [ClaudeBridge] Tunnel ready: https://....trycloudflare.com  <- give this address to the AI
   ```
   Адрес также записывается в `plugins/ClaudeBridge/tunnel-url.txt` и виден в `/claudebridge status`.
4. Передайте ИИ этот адрес, а токен из `token.txt` — через защищённую форму, не в чат.

Если туннель падает, плагин сам перезапускает его через 10 секунд, затем через 20, 40 и так далее, но не реже раза в 5 минут.

Если хостинг запрещает запускать программы, в консоли будет `Permission denied`. Если запрещает скачивать файлы, положите программу сами и укажите путь в `tunnel.binary`.

Учтите: трафик проходит через Cloudflare или ngrok. Они видят запросы, включая токен, поэтому выбирайте провайдера, которому доверяете.

## Установка на игровом хостинге с доменом и портом 443 (Let's Encrypt)

Это основной вариант: плагин сам получает бесплатный доверенный сертификат Let's Encrypt и сам его продлевает. Отдельный веб-сервер не нужен.

**Что понадобится:**
- домен или поддомен, например `bridge.example.ru`, с A-записью на IP сервера (`87.228.74.140`);
- на хостинге доступен **порт 443**, и он ведёт на этот сервер.

**Шаги:**
1. Положите `ClaudeBridge-1.3.0.jar` в `plugins/` и запустите сервер один раз. Создадутся `plugins/ClaudeBridge/config.yml` и `token.txt`.
2. В `config.yml` укажите:
   ```yaml
   http:
     bind: 0.0.0.0
     port: 443
     tls:
       mode: acme
       acme:
         domain: "bridge.example.ru"
         email: "you@example.ru"      # необязательно
         agree-tos: true              # прочитайте https://letsencrypt.org/repository/
   ```
3. Перезапустите сервер. В консоли через пару секунд появится:
   ```
   [ClaudeBridge] ClaudeBridge API listening on https://0.0.0.0:443
   [ClaudeBridge] ACME: requesting a certificate for bridge.example.ru ...
   [ClaudeBridge] ACME: certificate issued for bridge.example.ru by CN=..., O=Let's Encrypt, valid until ...
   ```
   Если выпуск не удался, в консоли будет причина с подсказкой, а следующая попытка — через час. Пока сертификата нет, API работает на временном самоподписанном сертификате.
4. Проверьте с любого компьютера: `curl https://bridge.example.ru/api` должен вернуть `{"error":"unauthorized: ..."}`. Так и должно быть: без токена API отказывает.
5. Сообщите ИИ адрес `https://bridge.example.ru`, а токен из `plugins/ClaudeBridge/token.txt` передайте через защищённую форму секретов, не в чат.

Сертификат продлевается сам, когда остаётся треть срока: проверка идёт каждые 30 минут, перезапуск не нужен. Хранится он в `plugins/ClaudeBridge/acme/`.

Если хостинг пробрасывает внешний порт 443 на другой внутренний порт, укажите в `http.port` внутренний порт.

## Другие варианты HTTPS

| `http.tls.mode` | Когда использовать |
|---|---|
| `acme` | Домен, и порт 443 ведёт на плагин (см. выше). |
| `off` | Веб-сервер (Caddy/nginx) на этой же машине проксирует на `127.0.0.1:8765`; `bind: 127.0.0.1`. |
| `self-signed` | Хостинг плюс отдельный веб-сервер. Плагин создаёт `plugins/ClaudeBridge/tls-cert.pem`, а веб-сервер закрепляет его (имя для проверки `claudebridge.local`). |
| `files` | Готовый сертификат, например от certbot: `http.tls.files.certificate` (цепочка) и `http.tls.files.private-key` (PKCS#8 или RSA PEM). Файлы перечитываются при изменении. |

Пример Caddy для режима `self-signed`:
```
api.example.ru {
    reverse_proxy https://HOSTING_IP:PORT {
        transport http {
            tls_trust_pool file /etc/caddy/claudebridge.pem
            tls_server_name claudebridge.local
        }
    }
}
```
Дополнительно можно ограничить клиентов: `http.allowed-ips: ["IP_веб-сервера"]`.

## Команды в игре (permission `claudebridge.admin`, по умолчанию у op)

| Команда | Что делает |
|---|---|
| `/claudebridge status` | состояние API и аватара |
| `/claudebridge on` / `off` | включить или мгновенно выключить API |
| `/claudebridge token` | выпустить новый токен (старый перестанет работать) |
| `/claudebridge tls` | `acme`: продлить сертификат сейчас; `self-signed`: новый сертификат; `files`: перечитать файлы |
| `/claudebridge reload` | перечитать конфиг и перезапустить API |
| `/claudebridge despawn` | убрать аватара из мира |

## Безопасность

- Токен 256 бит, сравнивается за постоянное время. Неверные попытки замедляются и пишутся в журнал.
- Каждый запрос пишется в `plugins/ClaudeBridge/audit.log`: время, IP, путь и параметры, включая текст команд.
- Файлы и базы доступны только на чтение. Выход за папку сервера заблокирован, в том числе через `..` и симлинки. Отдельные пути можно закрыть через `files.deny`.
- Любую часть можно выключить в `features:` в `config.yml`.
- Консоль даёт полный контроль над сервером. Перед началом сделайте бэкап мира.

## Ограничения

- Аватар — серверная фигура игрока, а не клиент. Его нет в списке игроков (Tab), у него нет голода и опыта.
- Блоки, которые ломает или ставит аватар, не видят плагины защиты территорий.
- Двери и кровати аватар пока не ставит, редстоун работает упрощённо.
- Базы H2 (`*.mv.db`) не поддерживаются.
- Мобы далеко от живых игроков «заморожены» сервером (entity activation range). Сам аватар при этом работает: у него своя физика.

## Проверено на Purpur 26.2 (сборка 2633)

- Старт плагина и API: HTTP, HTTPS с временным сертификатом, проверка токена.
- Режим `acme`: выбор проверочного сертификата по ALPN `acme-tls/1`, CSR, подпись JWS, проверочный сертификат по RFC 8737. Всё проверено OpenSSL и Go. Обмен с настоящим ACME-сервером здесь не проверялся.
- Консоль, логи, плагины, файлы (включая защиту от `../`), SQLite с защитой от записи.
- Аватар:
  - появление в незагруженных чанках и возвращение после перезапуска с инвентарём;
  - поиск пути в гору и вниз;
  - добыча с подходом и временем копания;
  - крафт (доски, верстак, палки, кирка);
  - установка блоков, сундук и печь (железо переплавилось);
  - бой с преследованием и подбором добычи;
  - падение с уроном, прыжок, чат.

## Сборка из исходников

Нужны JDK 25 и jar Purpur 26.2. Скрипт берёт API из самого jar сервера, а Gson, Guava и аннотации скачивает с Maven Central с проверкой SHA1.
```bash
./build.sh /path/to/purpur-26.2.jar
```

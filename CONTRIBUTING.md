# Как вносить изменения

## Собрать и проверить

```bash
cmake -S . -B build
```

```bash
cmake --build build -j
```

```bash
ctest --test-dir build --output-on-failure
```

Перед Pull Request тесты должны быть зелёными — GitHub Actions всё равно проверит.

## Добавить уровень

1. Скопируйте любой файл из `assets/levels/` и нарисуйте уровень символами:

   | Символ | Что это |
   |---|---|
   | `#` | блок |
   | `^` | шипы |
   | `P` | старт игрока (ровно один) |
   | `x` | жук |
   | `*` | пиксель (собирать) |
   | `S` | пружина |
   | `C` | чекпоинт |
   | `F` | финиш |
   | `1` / `2` | Алина (даёт двойной прыжок) / Егор (даёт рывок) |
   | `!` | сюжетная точка: разговор начнётся, когда герой пройдёт мимо |
   | `?` | осколок памяти: необязательная находка с кусочком истории |
   | `.` | воздух |

2. Первые строки файла — служебные:

   ```
   @title Название уровня
   @intro секция_из_story.txt        — разговор в начале уровня
   @talk  секция                     — по одной строке на каждый «!», слева направо
   @shard секция                     — по одной строке на каждый «?», слева направо
   ```

   Если число `!` и строк `@talk` не совпадёт, уровень не загрузится — это защита от разговоров без текста.

3. Добавьте имя файла в список уровней стадии в `src/main.cpp` (`kCrudeLevels` или `kPrettyLevels`).
4. Добавьте уровень в таблицу `kCases` в `tests/test_levels_playable.cpp` — бот проверит, что его можно пройти.

Ориентиры по физике (в клетках):

| | вверх | через пропасть |
|---|---|---|
| обычный прыжок | до 2 | до 3–4 |
| двойной прыжок | до 4 | до 6–7 |
| двойной прыжок + рывок | до 4 | до 10–11 |
| пружина | до 5 | — |

Ставьте чекпоинт перед каждым трудным местом и не сажайте жука туда, куда игрок приземляется вслепую.

## Добавить сектор терминала

Карта — 60×18 символов: `#` стена, `%` битый сектор (из него лезут жуки), `@` старт, `>` портал.
Правила сектора (сколько байт собрать, когда приходит Обнуление, есть ли тьма) — в `src/terminal/Sectors.cpp`.
Для реплик «голоса» после каждого байта добавьте в `story.txt` секции `terminal_s<сектор>_byte<номер>`.

## Поменять сюжет

Весь текст — в `assets/story.txt`. Формат и список героев описаны в начале файла,
общая картина — в [docs/STORY.md](docs/STORY.md).

- Финальная сцена существует в двух видах: секция `[epilogue]` (её показывает игра, пока нет видео)
  и сценарий для съёмки `assets/video/final_cutscene.txt`. Меняете одно — поправьте и другое.
- Реплики для 2D-стадий держите короче ~120 символов, иначе не влезут в окно диалога.
- Тесты проверяют, что у каждого разговора на уровнях есть текст, — запускайте их после правок.

## Стиль кода

- C++20, отступ 4 пробела, строки до 120 символов (`.clang-format` в корне).
- Имена: `ClassName`, `functionName`, `variableName`, поля класса с `_` на конце, константы `kName`.
- Комментарии — по-русски и про «зачем», а не «что».
- Логика (`src/core`, `src/platformer`, `src/terminal/TerminalWorld`) не должна подключать `raylib.h` —
  иначе её нельзя будет тестировать.
- Новая механика — новый тест.

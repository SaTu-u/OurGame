# Как вносить изменения

## Собрать и проверить

```bash
cmake -S . -B build
```

```bash
cmake --build build -j
```

```bash
ctest --test-dir build --output-on-failure
```

Перед Pull Request тесты должны быть зелёными — GitHub Actions всё равно проверит.

## Добавить уровень

1. Скопируйте любой файл из `assets/levels/` и нарисуйте уровень символами:

   | Символ | Что это |
   |---|---|
   | `#` | блок |
   | `^` | шипы |
   | `P` | старт игрока (ровно один) |
   | `x` | жук |
   | `*` | пиксель (собирать) |
   | `F` | финиш |
   | `C` | чекпоинт |
   | `1` / `2` | кент Глюк (двойной прыжок) / Шейдер (рывок) |
   | `B` | босс |
   | `.` | воздух |

2. Первые строки файла — служебные: `@title Название` и `@intro имя_секции_из_story.txt`.
3. Добавьте имя файла в список уровней стадии в `src/main.cpp` (`setup.levels`).
4. Добавьте уровень в тест `tests/test_levels_playable.cpp` — бот проверит, что его можно пройти.

Ориентиры по физике: обычный прыжок — около 3 клеток вверх и 4 вбок,
двойной — около 5 вверх, рывок — ещё 4–5 клеток по горизонтали.

## Поменять сюжет

Весь текст — в `assets/story.txt`. Формат описан в начале файла.
Если добавили новую секцию, которую вызывает код, добавьте её имя в тест в `tests/test_story.cpp`.

## Стиль кода

- C++20, отступ 4 пробела, строки до 120 символов (`.clang-format` в корне).
- Имена: `ClassName`, `functionName`, `variableName`, поля класса с `_` на конце, константы `kName`.
- Комментарии — по-русски и про «зачем», а не «что».
- Логика (`src/core`, `src/platformer`, `src/terminal/TerminalWorld`) не должна подключать `raylib.h` —
  иначе её нельзя будет тестировать.
- Новая механика — новый тест.

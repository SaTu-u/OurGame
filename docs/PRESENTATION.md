# План презентации (10–12 минут)

## Слайды

1. **Название.** «Из пикселя в люди». Команда, роли, ссылка на репозиторий.
2. **Идея в одной фразе.** «Игра улучшает графику по мере того, как растёт герой». Четыре скриншота стадий в ряд.
3. **Сюжет.** Пиксель, Глюк, Шейдер, Сборщик Мусора. Почему «Из пикселя в люди» — в финале пиксели становятся нами.
4. **Живое демо** (см. ниже) — главное, на это уходит больше всего времени.
5. **Кто что сделал.** Таблица ролей + скриншот `Insights → Contributors` + `git shortlog -sn`.
6. **Ветки и история.** Скриншот `Insights → Network`: три ветки участников, которые сливаются в `main`.
7. **Код.** Схема из [ARCHITECTURE.md](ARCHITECTURE.md): «мир один — графика разная». Пример `PlatformerRenderer`.
8. **Тесты и CI.** Зелёная галочка GitHub Actions, бот, который сам проходит уровни.
9. **Трудности и что узнали.** Каждый участник — по одной истории (что сломалось и как починили).
10. **Финальное видео** и спасибо.

## Сценарий демо

Каждую стадию можно запустить отдельно — не нужно проходить всю игру на защите.

| Шаг | Команда | Что показать |
|---|---|---|
| 1 | `pixel_to_people --new` | Игра стартует **в консоли**: загрузка BIOS, сюжет, пиксель убегает от жуков. Дождаться сборщика мусора |
| 2 | `pixel_to_people --stage 2` | «Драйвер кривой»: Paint-графика, WordArt, «Unregistered HyperCam 2», глитчи. Встретить Глюка |
| 3 | `pixel_to_people --stage 3` | Окно больше, всё светится. Пройти кусок уровня, показать частицы и тряску |
| 4 | Тот же уровень, но поиграть в стадии 2 и 3 по очереди | **Тот же прыжок, тот же мир — разная графика.** Это главный «вау» для преподавателя |
| 5 | `pixel_to_people --stage 4` | Пиксели исчезают → открывается видео → титры |

Совет: заранее запустите игру один раз (первая загрузка шрифтов и raylib), выключите уведомления,
увеличьте шрифт консоли, чтобы стадию 1 было видно с последней парты.
